# 패턴 알림 (카카오톡) 동작 정리

차트 패턴 탐지 → 카카오톡 알림 기능의 구조와, 실발송 테스트 과정에서 확정된
카카오 API 제약·설계 결정 기록.

## 동작 흐름

```
매일 06:30 (Asia/Seoul) 배치
  → 스캔 대상: TopSymbols.TOP_50 (나스닥·S&P 시총 상위 스냅샷) ∪ 전체 관심종목
  → 심볼별 일봉(1Y) 로드 → 피벗 추출 → ZigZag 정제 → 패턴 탐지
     (이중 천장/바닥, 헤드앤숄더/역헤드앤숄더, 컵앤핸들 — 넥라인 돌파 확정 시에만)
  → 신규 패턴만 저장 (극점 timestamp ±7일 중복 제거)
  → 차트 PNG 렌더링 → 카카오 이미지 업로드(CDN) → 카카오 토큰 보유 전체 회원에게 feed 메시지
```

- 알림 대상은 **카카오 토큰이 있는 전체 회원**이다. 과거에는 해당 종목을 관심종목에
  담은 사용자에게만 보냈지만, 스캔 유니버스가 관심종목보다 넓어지면서 전체 공지로 변경.
- 상위 50 목록은 `constant/TopSymbols`에서 수동 관리한다(무료 API 중 시총 순위를
  실시간 제공하는 것이 없음). 순위가 크게 바뀌면 이 파일만 수정.
- 카카오 토큰은 로그인 시 저장되며, 만료(401) 시 refresh 후 정확히 1회 재시도한다.

## 메시지 형태 (feed 템플릿)

```
[차트 이미지 800×400]
[패턴 감지] TSLA · 이중 바닥 (상승 반전)
주가가 패턴 경계선(넥라인)을 위로 뚫었어요. 무효화 가격 아래로 가면 신호는 취소돼요.
넥라인        $429.50
목표가        $644.30
무효화 가격    $214.71
[차트 보기] → 프론트 이동
```

- 설명(description)은 한 줄 요약, 가격 3종은 `item_content.items`(이름-값 행, 최대 5개)로 표시.
- 이미지 업로드 실패 시 텍스트 템플릿으로 폴백(가격 포함 2줄 본문).

## 실발송 테스트에서 확정된 카카오 API 제약

### 1. 이미지 업로드 multipart 필드명은 `file`

`/v2/api/talk/message/image/upload`는 문서 표기와 달리 필드명 `image`를
`{"msg":"unknown multipart entry. name=image","code":-2}`로 거부한다.
서버에서 `curl -F "image=@..."` vs `-F "file=@..."` 실측으로 **`file`이 정답**임을 확인.
이 버그 때문에 차트 이미지가 항상 텍스트 알림으로 대체되고 있었다.

- 업로드 성공 시 카카오 CDN URL 반환(약 3개월 보관) → 별도 이미지 저장소(S3 등) 불필요.
- CDN URL은 사용자 간 공유 가능하므로 심볼당 1회만 업로드한다.

### 2. feed description은 잘리고 "더보기"가 없다

카카오톡의 "더보기(전체보기)"는 일반 텍스트 채팅의 동작이고, **feed 템플릿
description은 표시 줄수를 넘으면 그냥 잘린다**. 긴 설명 대신:

- description → 한 줄 요약만
- 수치 정보 → `item_content.items` 행(잘림 없음)

### 3. 메시지 안에서 이미지 확대 불가

- 카카오톡 feed 메시지에는 이미지 뷰어(핀치줌)가 없다.
- 링크는 **개발자 콘솔에 등록된 도메인만** 열리므로, 이미지 탭 링크를 카카오 CDN
  URL(`k.kakaocdn.net`)로 걸어도 무시된다.
- 결론: 이미지/버튼 탭 모두 프론트로 보내고, 확대 보기는 프론트 차트 화면이 담당.

### 4. 발송 전제 조건

- 사용자 카카오 토큰이 DB에 있어야 한다(서비스에서 카카오 로그인 1회 이상).
- 카카오 로그인 scope에 `talk_message` 동의가 포함돼야 한다(403 = 동의 없음 → 재로그인 필요).
- 서버에 한글 폰트 필요(Dockerfile에서 `fonts-nanum` 설치) — 없으면 차트 라벨이 깨진다.

## 테스트 방법

실제 패턴은 드물게 발생하므로(넥라인 돌파 확정 조건) 발송 경로 검증용 엔드포인트를 사용한다:

```bash
# 탐지만 (발송 없음)
curl -X POST "https://<백엔드>/test/patterns/run?symbol=AAPL&dryRun=true"

# 샘플 패턴으로 본인에게 실발송 (운영 발송 코드 그대로, 탐지/저장 없음. 인증 필요)
TOKEN=$(curl -s https://<백엔드>/test/token)
curl -X POST "https://<백엔드>/test/patterns/send-sample?symbol=TSLA" \
  -H "Authorization: Bearer $TOKEN"

# 전체 배치 즉시 실행 (신규 패턴이 있으면 실제 발송됨)
curl -X POST "https://<백엔드>/test/patterns/run"
```

`/test/token`, `/test/patterns/run`은 인증 없이 열려 있으므로 운영에서 차단(프로파일 분기) 필요 — TODO.
